## Как сообщить об уязвимости

**НЕ открывайте публичный issue** для уязвимостей и утечек данных.

### Предпочтительный способ: GitHub Private Vulnerability Reporting

1. Перейдите во вкладку **Security** этого репозитория
2. Нажмите **Report a vulnerability**
3. Заполните форму с деталями

### Альтернатива: Прямой контакт

Если приватный репорт недоступен, свяжитесь с мейнтейнером:

- **GitHub:** [@DenisZakharov2](https://github.com/DenisZakharov2)
- **Email:** `security@denis-zakharov.ru`

### Что указать в репорте

- Затронутый файл(ы) или артефакт(ы)
- Шаги воспроизведения
- Потенциальное влияние
- Предлагаемое исправление (если известно)

### SLA ответа

- **Подтверждение получения:** в течение 48 часов
- **Триаж и первичная оценка:** в течение 7 дней
- **Цель исправления:** Critical/High — 30 дней; Medium/Low — следующий релиз

## Область действия (Scope)

Репозиторий содержит **документацию, схемы, скиллы и примеры** для Hermes Protocol.

### В зоне ответственности (In Scope)

- Обход валидации JSON Schema
- XSS/SSRF через Mermaid-диаграммы
- Инъекция в шаблоны Marp/PPTX/Typst (`research-synthesist`)
- Персональные данные (PII) в примерах артефактов (`*_flight_log.json`, `business_requirements.example.json`)
- Случайно закоммиченные API-ключи/секреты в примерах
- Supply chain: `npm` зависимости в `package.json` (только devDependencies)

### Вне зоны (Out of Scope)

- Hermes Agent runtime (репортить его мейнтейнерам)
- Базовые LLM / провайдеры моделей
- Инфраструктура, развёрнутая пользователем

## Лучшие практики для контрибьюторов

1. **Никогда не коммитьте реальные PII, пароли, API-ключи, токены** — используйте плейсхолдеры (`REDACTED`, `{{API_KEY}}`)
2. **Валидируйте все примеры** перед коммитом: `npm run validate`
3. **Периодически запускайте `npm audit`** — Dependabot алерты включены
4. **Mermaid-диаграммы** — CI разбирает диаграммы из `docs/diagrams/` реальным парсером `mermaid.parse` в режиме `securityLevel: 'strict'` (тот же режим, что и в репозитории). Не вставляйте в диаграммы HTML или скрипты: строгий режим их отвергнет
5. **Flight logs** — убедитесь в `mask_pii: true` при валидации схем (будущее улучшение)

## Политика раскрытия (Disclosure)

Следуем coordinated disclosure. После выпуска исправления:

1. Публикуем GitHub Security Advisory
2. Указываем репортера в кредитах (если не просит анонимности)
3. Обновляем `CHANGELOG.md` с тегом `[Security]`
